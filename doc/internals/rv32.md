## Target

| | |
|---|---|
| Spelled | `-a:rv32`, or `--os:linux --cpu:riscv32` |
| Core | **RV32IM** — the 32-bit base plus the multiply extension |
| Hosted, not bare metal | This is the sibling of `linux_arm64`, not of `cortex_m`. `qemu-riscv32` runs a Linux user-mode binary, so stdout and the exit status come from `write` and `exit` — no board file, no vector table, no semihosting. |
| Why RV32IM | RV32I alone has no multiply at all, so every `a * b` would be a runtime helper. `M` is present on every real 32-bit part and is what `rv32im` means to every other toolchain. Not `C` (compressed): it halves some instructions and doubles the encoder. |
| Word | 4 bytes |
| Syscalls | The asm-generic numbers, shared with RV64 and AArch64: `write` is 64, `exit` is 93. Number in `a7`, arguments in `a0`..`a5`, `ecall`, result in `a0`. |
| Float | No FPU assumed (`ilp32` soft float). `F`/`D` are a later flag, not a second backend. |

## Test host

```
qemu-riscv32 image
```

Already installed here, and needs nothing else: a static ELF32 for `EM_RISCV`
runs directly. That makes RV32 the cheapest target in the tree to test — the
`.exitcode` oracle every other corpus uses works with no simulator protocol at
all, because the exit status is a real `exit` syscall.

## The one thing R0 was written to catch

**Two PT_LOADs must not share a page.** Every field in the ELF header can be
right — the `p_offset ≡ p_vaddr (mod p_align)` congruence included — and the
program still dies at its first instruction, because two segments landing in one
page have that page's permissions decided by whichever is mapped last. An R+X
segment sharing a page with an RW one silently stops being executable.

The symptom is a SIGSEGV at the entry point with nothing in the image wrong. R0
puts the data segment a whole page above the code, and says why at the site.

## Where RISC-V does NOT fit the existing vocabulary

Cortex-M cost almost nothing to add because Thumb-2 and AArch64 share the asm-NIF
vocabulary at the instruction level: `add3`, `cmp`, `beq`, `ldr` mean the same
thing on both, so `generateM` is the AArch64 emitter driven with a different
machine model. RV32 is three-operand and register-rich, so it looks like the
best candidate yet for that treatment.

**It is not, and the reason is that RISC-V has no condition flags.** There is no
status register, so `(cmp D S)` followed by `(beq L)` describes nothing this
machine does. A comparison is either `slt`/`sltu` producing a 0 or 1 in a
register, or it is fused into a two-register `beq rs1, rs2, label`. Both are
shapes the shared vocabulary cannot spell.

So RV32 needs its own selector and its own value core — the same conclusion AVR
reached, for a completely different reason. What it does NOT need is a new
register allocator: `planer.allocateProc` is arch-neutral and takes a
`MachineDesc`, which is what made AVR's M4c the emitter alone.

The vocabulary RV32 adds is therefore compare-and-branch plus set-less-than:

| tag | meaning |
|---|---|
| `(beqr A B L)` … `(bgeur A B L)` | branch on a two-register comparison — the six the hardware has |
| `(slt D A B)` / `(sltu D A B)` | 1 if A < B, else 0 — how a bool is materialized |
| `(slti D A K)` / `(sltiu D A K)` | the same against a 12-bit immediate |

`(jal L)`, `(jalr D A K)`, `(lui D K)`, `(auipc D K)` and the `i`-suffixed ALU
forms follow the same rule: one tag, one instruction.

## Register model (planned)

Slots `R0`..`R30` map to `x0`..`x30`; `x31` is unmapped, which costs nothing at
30 allocatable registers. The `SP` slot is `x2` as on the Arm targets.

| role | registers |
|---|---|
| reserved | `x0` (hardwired zero), `x1` (ra), `x2` (sp), `x3` (gp), `x4` (tp) |
| arguments / return | `a0`–`a7` = `x10`–`x17`; `a0` returns |
| callee-saved | `s0`–`s11` = `x8`, `x9`, `x18`–`x27` |
| temporaries | `t0`–`t2` = `x5`–`x7`, `t3`–`t4` = `x28`–`x29` |
| bridges | `x30`, `x29` (staging) |

**Two bridges, and the first draft of this file said one.** The count is what
the widest sequence needs live at once, and the sequence is not arithmetic — a
three-operand ALU with a ±2 KB load/store off any register really does let a
spilled operand go straight into the instruction that wants it.

It is the COMPARISON. A branch here compares two registers; there is no `blti`
and no flag to leave an answer in. So `x < 10` with `x` already in the bridge has
nowhere to put the 10, and one bridge silently compared the constant with itself
— which is how `branch` and `loop` failed on their first run, with plausible
wrong answers rather than a crash.

Two is still the minimum: the second is live for exactly one instruction, and
nothing nests inside that window because an operand that has to be COMPUTED is
parked in a frame slot first.

**`x0` is the whole reason this file is short.** There is no `mov`, no `neg`, no
`not` and no `nop` on this machine, and none is missing: each is one ordinary
instruction with the zero register as an operand. The emitter spells them that
way rather than asking the assembler to invent anything.

### What R3 has

`src/nifasm/rv32/` — `regs.nim`, `operands.nim`, `instr.nim` — plus
`image/writerv32.nim`. Six hand-written fixtures in `tests/tester`: the ALU, a
compare-and-branch, a `loop` closed by a forward `bge`, a frame slot through SP,
a proc call with register arguments, and a `hello` that prints through `write`.

Two things the other targets needed and this one does not: no register tag was
minted (`(x0)`..`(x30)` and `(sp)` are AArch64's, reused), and no bridge is
consumed by the selector — one addressing mode and a three-operand ALU mean an
operand is loaded straight into the register the instruction wants.

One thing it needs that they do not: **`(ite …)` and `(jtrue …)` are refused by
name.** Both are built on the x86 FLAG vocabulary, and this machine has none, so
a condition is not a thing that exists between two instructions here. Control
flow is `(beqr A B L)` and its five siblings.

The frame is `(sub (sp) (ssize))` and `(add (sp) (ssize))`, as on every other
target. The placeholder carries the SIGN — `addi sp, sp, -1` for a subtract, 0
for an add — because the two are the same instruction on this machine and the
patcher has no other way to tell which one it is looking at.

### A latent bug R3 turned up

The `plain(…)` template that emits a childless instruction did `inc n` followed
by draining `hasMore`. `inc` steps INTO the node, and `hasMore` is then relative
to the enclosing `(stmts …)` — so the drain swallowed every statement after it.
It was invisible on AVR because `(ret)` is always last in a proc body; the first
`(ecall)` of `hello_rv32` sat in the middle of one, printed correctly, and then
fell through into its own string constant. Both selectors now `skip` the node.

### What R4 has

`src/arkham/rv32/` — `machine.nim`, `emit.nim`, `gen.nim`, `driver.nim` — driven
by the arch-neutral `allocateProc`. A destination-passing value core in the shape
`src/arkham/avr/gen.nim` established, and markedly shorter than it: a
three-operand ALU means an operand never has to be moved into the destination
first, one addressing mode means a spilled operand is loaded straight into the
register that wants it, and `x0` makes `mov`, `neg`, `not` and
compare-against-zero ordinary instructions.

Ten fixtures in `tests/arkham_rv32`. Eight are the AVR corpus with `(i 16)`
rewritten to `(i 32)` — the same programs on a machine with four times the word
and thirty registers instead of sixteen pairs, which is the comparison worth
having; `divmod` and `wide` are RV32's own, exercising a divide and a modulo AVR
has no instruction for at all and a constant that needs `lui`+`addi`.

**No flags is a simplification, not a complication.** A comparison used as a
condition is a two-register branch and one used as a value is `slt` — never a
flag left between two instructions. There is no window in which a comparison's
result can be clobbered, so there is nothing to protect.

## What R2 established

`src/nifasm/rv32/encoder.nim`, dependency-free and in the shape of the other
three. Three relocation kinds, and the interesting thing about them is what they
do NOT have to do: every RV32 instruction is four bytes, so unlike AVR nothing is
halved and unlike Thumb nothing changes width. What they do instead is REBUILD
the immediate from the distance and OR it back over the fields it owns, which is
why one kind serves all six branch conditions and another serves both `jal`
forms — the condition and the link register survive from the placeholder.

`tests/rv32_selftest.nim` computes 51 expressions and exits with the index of the
first wrong one, then rebuilds itself 51 more times with one expectation
corrupted each time and requires every one of those to fail with exactly that
index. `tests/tester` runs the whole sweep.

Two checks earn their place beyond the obvious: `lui`+`addi` with a low half
ABOVE 0x7FF — the compensation case, where omitting the `+0x800` is wrong by
exactly 0x1000 — and a branch over 200 instructions, since the field the patcher
permutes is only exercised past the first few bytes.

## What R0 established

`tools/rv32_probe.nim` hand-builds a static ELF32 that self-checks 13 encodings
and exits with a value it computed. Each check exits with its own 1-based index
on mismatch, so a failure names the broken encoding.

```
nim c -o:bin/rv32_probe tools/rv32_probe.nim
bin/rv32_probe /tmp/rv.elf 42
qemu-riscv32 /tmp/rv.elf ; echo $?      # 42
```

Covered: the ELF shape and the page separation above, both syscalls, the
`lui`+`addi` materialization *including* the low-half-above-0x7FF case that a
naive split gets wrong by exactly 0x1000, `add`/`sub`/`and`, `mul`, `slt` both
ways, `slli`/`srai`, `sw`/`lw` through SP, a backward `bne` closing a counted
loop, and `jal`/`jalr`.

The B and J immediate formats are the ones worth the checks: their fields are in
halfword units with bit 0 implicit, and the bits are permuted rather than merely
shifted — bit 11 of a branch offset sits below the sign bit, in the slot a
careless reading gives to bit 4.
